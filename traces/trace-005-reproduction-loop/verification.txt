Fourth diagnosis
----------------

Two independent problems remained:

1. Evidence constraint enforcement was only prompt-level. The system told the Verifier not to contradict tool output, but did not mechanically reject an impossible `complete_fix` verdict.

2. Batch evaluation had poor operational behavior: no per-case progress display, a long provider timeout, no partial checkpoint file, and a provider/validation failure could abort the entire batch.

Fourth fix applied
------------------

Deterministic verdict gate:
- Iteration 2 now computes explicit reasons that forbid `complete_fix`.
- `complete_fix` is forbidden when the patched existing suite fails or times out.
- `complete_fix` is forbidden when a generated reproduction fails on the original and the same test still fails on the patch.
- these constraints are supplied to the Verifier before its model call;
- after the model call, a deterministic post-check enforces the constraints even if the model ignores them;
- a conflicting model `complete_fix` is conservatively converted to `inconclusive` rather than allowing approval;
- `result.json` records the model-proposed verdict, final verdict, whether the gate overrode the model, and the exact constraint reasons.

Batch robustness and observability:
- `eval-advanced` now prints per-case progress such as `[1/10] case_001 ...` and a result/runtime line after each case;
- each completed case is checkpointed to `cases.partial.jsonl` immediately;
- provider/validation errors are recorded as per-case errors and the batch continues instead of losing all prior work;
- the final summary reports completed cases, errors, and whether the evaluation completed cleanly;
- batch metrics with errors are explicitly marked as not cleanly comparable until the errors are resolved.

Provider latency control:
- language-model request timeout is now configurable with `--llm-timeout` or `REFUTE_LLM_TIMEOUT`;
- the CLI default is 30 seconds instead of an implicit 120-second provider wait;
- Iteration 2 batch evaluation uses one Investigator/Verifier provider attempt per case so one stuck request cannot silently consume multiple long retries;
- Reproducer attempts remain bounded and configurable.

Automated coverage added:
- a test now reproduces the exact failure class seen locally: generated test fails on original and patch, Verifier proposes `complete_fix`, deterministic gate must return `inconclusive` and record the override.
